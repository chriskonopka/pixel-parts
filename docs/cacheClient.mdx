# Cache Client

A lightweight, **IndexedDB cache client** that provides an easy asynchronous API for storing, retrieving, and managing cached data in the browser.

## Site/Tenant Based Scoping

All items are scoped respective to the site name. 

For example, all items cached on `https://mcdermottwillemery.sharepoint.com/sites/ai` will be scoped to `site/ai`. So, saving an item with a key named `profiles` will be scopes as `site/ai/profiles` in IndexedDB.

#### The benefits of scoped keys include:

- **Prevents key collisions** – ensures different sites, hostnames, or tenants don’t overwrite each other’s cached data.
- **Isolates data per site or tenant** – each site has its own logical “namespace” in the same database.
- **Improves security and privacy** – avoids data leakage between users, sites, or environments.
- **Enables targeted cleanup** – allows deleting all cache entries for a specific site without touching others.
- **Simplifies expiration management** – cleanup and expiry routines can efficiently operate within one site scope.
- **Improves debugging clarity** – scoped keys make it easy to see which site or environment data belongs to in DevTools.
- **Supports multi-environment apps** – works seamlessly across dev, staging, and production without shared key conflicts.
- **Future-proofs caching** – easily extends to multi-tenant, subdomain, or embedded app scenarios without refactoring.
- **Keeps storage efficient** – avoids redundant global databases for each context by isolating within a single IndexedDB store.
